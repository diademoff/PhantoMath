# Драйвер телефона и эмулятора: сценарии задач и скриншоты

`drive.py` проходит сценарий задач на устройстве и складывает скриншоты и
видимые тексты. Нужны только `python3` (стандартная библиотека), `adb` и
ImageMagick (`montage`).

Все нажатия — по центрам элементов из `uiautomator dump`, а не по
фиксированным координатам: раскладка клавиатуры зависит от экрана. Дампы
пишутся в `/sdcard/student_drive_<серийник>.xml` на устройстве и в
`OUTDIR/_ui_<серийник>.xml` на хосте, поэтому телефон и эмулятор можно
запускать одновременно.

## Запуск

```sh
ANDROID_SERIAL=0B051JECB02587 python3 tools/device/drive.py \
    tools/device/example_tasks.json out/phone [--only det2] [--no-shots] \
    [--install app/build/app/outputs/flutter-apk/app-release.apk]
```

`ANDROID_SERIAL` можно не задавать, если подключено ровно одно устройство.
`--install` ставит APK (`adb install -r`) перед прогоном и ждёт загрузку
устройства (до 5 минут). `--no-shots` не снимает скриншоты и не собирает
контактный лист: остаются только текстовые дампы экранов.

Перед каждой задачей приложение перезапускается (`am force-stop` + `am start`)
и драйвер ждёт клавиатуру: первые нажатия после старта теряются.

## Файл задач

Список задач: `[{"id", "note", "actions": [...]}]`. Действия:

| действие | что делает |
|---|---|
| `{"key": "OPERATOR_DETERMINANT"}` | нажать клавишу по коду оператора или по её подписи (`{"key": "Матрица"}`); экран клавиатуры переключается сам |
| `{"long_press": "OPERATOR_LIMIT"}` | долго нажать клавишу — открывается лист вариантов (`{"tap_text": "Предел справа"}`, `{"tap_text": "Производная n-го порядка"}`) |
| `{"type": "12"}` | набрать клавишами: цифры, латинские буквы (`x` → клавиша `x`), `. - + * / = ( )` |
| `{"next": 1}` | нажать «Далее» n раз (кнопка исчезает, когда слоты кончились) |
| `{"dialog": {"size": 3}}` | диалог размера определителя: размер, «Вставить» |
| `{"dialog": {"rows": 2, "cols": 3}}` | диалог размера матрицы: строки, столбцы, «Вставить» |
| `{"tap_text": "Ранг"}` | нажать элемент с такой подписью; список прокручивается, пока текст не найдётся |
| `{"input": "4,6;2,1"}` | набрать в поле ввода (`adb shell input text`, `;` и пробелы экранируются) |
| `{"input": {"text": "4,6;2,1", "clear": true}}` | то же, но сначала стереть текст, который уже стоит в поле (в шторке матрицы это «5,6;7,8») |
| `{"solve": true}` | нажать «Вычислить»/«Шаги решения» и дождаться экрана шагов |
| `{"shot": "name"}` | снимок и текстовый дамп видимых подписей |
| `{"tour": {"stages": 8, "details": 1}}` | на экране шагов: снимок карточки, до N нажатий «Далее» (снимок после каждого), до D открытий «Подробнее» (снимок и назад) |
| `{"back": 1}` | системная кнопка «назад» |
| `{"clear": true}` | кнопка ⊗ «Очистить» |
| `{"wait": 0.5}` | пауза, секунды |

Необязательное поле задачи `expect_answer` (подстрока LaTeX) сверяет ответ
с `content-desc` карточки ответа после `solve`: строка лога кончается `ok`
или `mismatch: <got>`.

## Результаты

* `OUTDIR/<id>/NN_<name>.png` — скриншоты в порядке съёмки (нет с `--no-shots`);
* `OUTDIR/<id>/NN_<name>.txt` — видимые подписи этого экрана (`text` и
  `content-desc`) сверху вниз: `y,x kind value`;
* `OUTDIR/transcript_<id>.md` — те же подписи всех снимков задачи по порядку;
* `OUTDIR/<id>/texts.txt` — видимые тексты (`text` и `content-desc`) каждого
  дампа по порядку; блоки разделены строкой `--- <действие>`, переводы строк
  внутри подписи записаны как `\n`;
* `OUTDIR/sheet_<id>.png` — лист из всех снимков задачи
  (`montage … -tile 6x -geometry 270x585+4+4`);
* `OUTDIR/run_<серийник>.log` — ход прогона.

Самопроверка без устройства (порядок подписей и transcript на сохранённом
`uiautomator` XML): `python3 tools/device/drive.py --self-test`.

Если действие не удалось, драйвер снимает `NN_error.png`, пишет ошибку в лог и
переходит к следующей задаче. Итог — одна строка на задачу: id, секунды,
сколько снимков, `ok` или `error: …`; код возврата 1, если была хоть одна
ошибка.

Для отладки нажатий: `STUDENT_DRIVE_DEBUG=1` дописывает координаты каждого
тапа в лог.

## Пример

`tools/device/example_tasks.json` — две задачи: определитель `|3 5; 2 4|`
(ответ 2, тур по этапам) и ранг `[[1,2,3],[2,4,6],[1,1,1]]` (ответ 2) через
«Другие действия» → «Матрица…» → «Ранг».
