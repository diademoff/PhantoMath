# PhantoMath

Flutter-клиент: ввод выражения, отправка в бэкенд, показ пошагового
объяснения. Целевая платформа — Android.

Формат обмена с бэкендом — контракт Photomath
(`truth/03-solver-contract.md`): на входе `CoreNode`, на выходе
`CoreSolverData` с вертикальными шагами.

## Требования

| Что | Версия |
|---|---|
| Flutter | 3.47.7 stable (Dart 3.13.5) |
| JDK | 17+ (для Gradle) |
| Android SDK | platform 36, build-tools 36.0.0 |

## Сборка

Релизный APK со **встроенным Python-решателем** (см. ниже). Из корня
репозитория:

```bash
make apk        # упакует Python (sympy + mymath_backend) и соберёт release APK
make serve      # раздаст APK по tailnet
```

Напрямую через Flutter — после `make python-bundle`, с переменными упаковщика
во всех вариантах сборки (debug/profile/release):

```bash
make python-bundle
export SERIOUS_PYTHON_SITE_PACKAGES="$PWD/app/build/site-packages"
export SERIOUS_PYTHON_APP="$PWD/app/build/python-app"
export SERIOUS_PYTHON_VERSION=3.12
cd app
flutter build apk --release
```

Для profile-сборки используйте те же переменные и `flutter build apk --profile`.

## Запуск с бэкендом

**На Android решатель встроен в приложение.** Проверки не требуют сети:
при старте поднимается локальный сервер на `127.0.0.1:8770`
(`lib/src/api/embedded_backend.dart`). Редактор доступен с первого Flutter-кадра;
`SolverStartup` отслеживает готовность отдельно. Ввод во время загрузки не теряется,
а изменение задачи отменяет ожидающую отправку. Ошибка запуска предлагает повтор,
без незаметного переключения на неработающий адрес эмулятора.
Если `MYMATH_API` задан, встроенный Python не
запускается — удобно для разработки на десктопе с внешним FastAPI:

```bash
flutter run --dart-define=MYMATH_API=http://10.0.2.2:8000   # эмулятор + внешний бэкенд
```

`10.0.2.2` — адрес хоста, видимый с эмулятора Android. Внешний бэкенд надо
поднимать с `--host 0.0.0.0`. На физическом устройстве без встроенного
Python нужен реальный IP машины в tailnet.

## Состав

| Файл | Что внутри |
|---|---|
| `lib/main.dart` | Экран ввода и результата |
| `lib/src/model/core_node.dart` | `CoreNode` и `CoreNodeType` — зеркало Python-модели |
| `lib/src/api/solver_api.dart` | HTTP-клиент: `solve`, `parse`, `isHealthy` |
| `lib/src/api/embedded_backend.dart` | Запуск встроенного Python и ожидание его готовности |
| `lib/src/render/latex.dart` | `CoreNode` → LaTeX для `flutter_math_fork` |
| `python/` | Python-программа на устройстве: `main.py` (сервер), `requirements.txt` |
| `test/model_test.dart` | Разбор ответа, перевод в LaTeX, поведение клиента при ошибках |

## Встроенный Python на устройстве

Решатель — это Python, и он **лежит в APK**. На Android приложение запускает
CPython (пакет `serious_python`) в фоновом потоке; программа
`python/main.py` поднимает локальный сервер решателя (`mymath_backend.device`,
stdlib `http.server`) на `127.0.0.1:8770`, а приложение ходит к нему обычным
HTTP-клиентом. Ядро бэкенда не тянет `pydantic`/`fastapi` — модели контракта
dataclasses, а зависимости свелись к чистому `sympy` (см.
`../truth/09-decisions.md`), поэтому упаковка в APK не требует NDK.

`make python-bundle` копирует `backend/mymath_backend` и
`truth/data/explanations.json` в `app/python/` (это сгенерированные копии,
они в `.gitignore`) и упаковывает их вместе с `sympy` через `serious_python`.
Размер APK растёт заметно (CPython, stdlib и sympy для трёх ABI) — это плата
за работу без сети.

## Как это устроено

**Рендер.** Формулы рисует `flutter_math_fork`: наш `nodeToLatex` переводит
дерево в строку LaTeX с позиционными плейсхолдерами `$0`, `$1`, … — по
одному на ребёнка. Это позволяет разводить аргументы по разным местам:
`\frac{$0}{$1}` кладёт первого в числитель, второго в знаменатель.
Результат — «сырой» LaTeX без обёрток `$…$`: парсер (`KaTeX`) не принимает
`$` внутри формулы. Свой рентер дробей и корней не писался сознательно:
это отдельный проект.

**Объяснения.** Ответ, исходная и преобразованная формулы видны без раскрытия.
«Пояснить этапы» раскрывает существующие детали, а не отправляет задачу повторно.
Для распределительного закона, сокращения числовых дробей и двойного минуса
есть управляемые учебные сцены. Неподдержанные правила остаются текстовыми.

**Деление.** Локальная трасса на `BigInt` визуализирует деление двух неотрицательных
целых чисел длиной до 12 цифр, с ненулевым делителем. Учитывает нули, конечные
десятичные дроби и повторение остатка. После 12 десятичных разрядов явно сообщает
об ограничении, не выдавая приближение за конечный точный ответ. Это представление
не подменяет ответ Python-решателя. Для десятичных/отрицательных исходных операндов
столбиковое занятие пока не предлагается.

**Тема.** Семантические роли в `lib/src/theme/phanto_theme.dart`, светлая и тёмная
схемы, `themeMode: system`. Нативный splash и launcher используют собственный знак.
Анимации учитывают Reduced Motion и не блокируют ввод.

**Ввод.** Структурный редактор строит дерево локально. Каретка адресует слоты и
символы внутри числового токена; публичный `CoreNode` и HTTP-контракт не изменены.
Перед удалением заполненный шаблон выделяется. Буквенная раскладка сохраняется;
все символы доступны явно, долгое нажатие — дополнительный быстрый путь.

**График.** Отдельный экран: pan/zoom, кнопки масштаба, «По центру», выбор точки,
список корней, экстремумов, пересечений и асимптот. При изменении диапазона точки
запрашиваются заново; устаревшие ответы игнорируются. Метки ограничены данными
существующего `GraphData`: фокусы коник и несколько независимых кривых не добавлены.
Полноту особых точек и всех разрывов числовая выборка не гарантирует.

**Ошибки.** `422` от бэкенда — это «задача не решилась», а не сбой: показываем
текст пользователю. `5xx` и сетевые сбои идут в `SolveFailure` с кодом.

**Неизвестные типы узлов** не роняют разбор: подставляется `TEXT` с
сохранением значения, а `CoreNode.hadUnknownTypeIn` позволяет их отследить.
Расхождение с бэкендом должно быть заметным, а не тихим.

## Чего ещё нет

- Локализация интерфейса: строки пока только русские (решение пользователя);
  переключатель языка меняет только язык пояснений (ru/en).
- Контраст основных семантических пар проверяется в `test/theme_test.dart`.
  Размеры клавиш, маленькие окна, landscape и двойной масштаб текста проверяются
  в `test/adaptive_test.dart`. Полный ручной аудит TalkBack ещё необходим;
  эти тесты не являются сертификацией всего интерфейса по WCAG.

## Регрессия на USB-устройстве

Сначала экспортируйте переменные упаковщика из раздела сборки. Затем:

```bash
flutter test integration_test -d <device-id>
```

Телефон должен оставаться разблокированным с включённым экраном: Live binding
не может завершать кадры в Doze. Для длинного USB-прогона можно временно включить
`adb -s <device-id> shell svc power stayon usb`, предварительно сохранив
`adb -s <device-id> shell settings get global stay_on_while_plugged_in`.
После прогона восстановите сохранённое значение через `settings put global`.

`ux_regression_test.dart` проверяет ввод до готовности, отмену устаревшего запроса
и отсутствие повторной отправки при раскрытии объяснений. `smoke_test.dart`
использует настоящий встроенный решатель для арифметики, уравнения, системы,
ошибок, факториала, деления столбиком и графика.
