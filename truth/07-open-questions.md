## Q2. Связь `CoreAnimationCommandResult.command` ↔ id в model.json

`command` — строка (`"ADD"`, …), а `model.json` озаглавливает потоки **id**
(`16`, `67`, `100`, …). Прямого отображения не найдено.

Гипотезы: `CoreAnimationResultType` (`ADD`…) → свой id; либо потоки
адресуются через `name`. Не проверено.

**Влияние:** только на вариант C (полный паритет анимаций). Не блокирует MVP.

## Q7. Как получить эталонные ответы решателя

Для верификации нужны реальные выходы `nativeProcessExpression`. Варианты:

1. **Установить APK на эмулятор/устройство** и снять вывод через Frida
   (перехват `nativeProcessExpression` / парсинг логов).
   REA умеет `install_adb_package` и `resume_frida_session`.
   Риск: arm7-only ABI → нужен x86-эмулятор с ARM-транслятором или
   arm64-устройство. Неизвестно, работает ли.
2. **Ответить на задачи в приложении вручную** и записать вывод.
   Медленно, но надёжно.
3. **Реконструировать из arsc**: у нас есть все ключи и их арность, но нет
   самих задач.

Рекомендация: вариант 2 для корпуса из 50-100 задач (основные модули),
далее вариант 1 если нужен массовый сбор.

## Q10. ~~Протечка шага подвыражения в ответ~~ — **ЗАКРЫТ**

Найдено тестовым корпусом (`backend/tests/corpus/`). Верхний `solve()`
(`solver/__init__.py`) брал ответ из **последнего записанного шага**
(`_final_value`), а не из значения, которое вернул `route(node, ctx)`.
Следствие: если модуль сворачивал подвыражение (`route(child, ctx)` пишет
шаг) и затем решал **оставить свой узел**, шаг подвыражения становился
финальным ответом (`√(2+3)` → `5`, `log₁₀(2+3)` → `5`, `∛(1+1)` → `2`).

**Исправлено:**

1. `solve()` берёт ответ из значения `route()` (`_final_value` удалён).
2. Добавлен `base.fold_semantically(node, ctx)`: сворачивает подвыражение в
   служебном накопителе и переносит шаги только при успехе. Модуль, который
   оставляет узел, теперь возвращает его **со свёрнутыми детьми**:
   `√(2+3)` → шаг `2+3 = 5`, ответ `√5`; `log₁₀(2+3)` → `log₁₀(5)`;
   `∛(1+1)` → `∛2`; `√(-4)` остаётся `√(-4)`.
3. Кейсы возвращены в корпус (`corpus/powers.json`), плюс юнит-тесты в
   `tests/test_solver_powers.py` (`TestKeptNodeFoldsChild`).

**Тригонометрия** тоже сворачивает аргумент (`sin(1+1)` → шаг `1+1 = 2`,
ответ `sin(2)`), но только **после** проверок чётности и периодичности:
`sin(-1)` по-прежнему даёт `-sin(1)`. В корпусе дроби-аргументы записаны
узлом `frac(...)` (как в редакторе), а не знаком `/`: протокольное `1/2` --
это узел `DIVIDE`, и его свёртка даёт лишний шаг `div`.
