# 11. Остаточный roadmap: разрыв с APK 7.10.0

Составлен по итогам сверки бэкенда `mymath` с APK (источник истины). Учитывает
`truth/10-solver-roadmap.md` (первичный план) и фактическое состояние на момент
обновления: зарегистрировано 118 типов узлов из 143, корпус 68 модулей / 348
задач, шаги ссылаются на ~218 ключей из 3252.

Правила те же (см. `00-INDEX.md`): без сроков и оценок времени — только
приоритеты и сложность; продуктовые решения за пользователем.

## 11.1. Как читается

Формат блока: **что не сходится**, типы узлов, группы ключей, зависимости,
приоритет/сложность. Приоритеты: **P1** — реальный разрыв возможностей (APK
даёт результат, которого у нас нет), **P2** — расширение/глубина, **P3** —
нишевое/по решению. Отдельно помечено, что относится к варианту B (анимации).

Числа ключей — из `truth/data/explanations.json`; «не используется» — нет ссылок
из решателя и корпуса.

## 11.2. Что закрыто (кратко)

N (множества/интервалы/сравнение), D (область определения + явные шаги ОДЗ),
A (уравнения общего вида, в т.ч. параметрические), B (неравенства общего вида,
в т.ч. с модулем), C (системы n×n и нелинейные), E (чётность, экстремумы,
перегибы, асимптоты, вершина, пересечения с осями, область значений, ось
симметрии, форма по корням, наклонная асимптота, число пересечений), G
(последовательности: прогрессии, явная формула, сходимость), H (суммы и 4
признака сходимости), K (методы интегрирования, площадь, несобственные с
разрывами, повторные, простейшие дроби, подстановка пределов), L (комплексные:
полярная форма, степень, корни, умножение/деление в полярной), O (проценты,
перезапись, единицы, периодические дроби, округление, ДМС, y=kx+b), Q
(доказательство тождеств), R (подстановка, значение функции, обратная функция,
вычисление выражения, среднее), I (дифференциальные уравнения), M (матричные
уравнения, обратная по Гауссу, элементарные преобразования строк), P (столбиковые
вычисления — результат). J — производные (правила, высших порядков, штрих,
Лейбниц).

## 11.3. Направления

### R1. Конические сечения — полный разбор — P1, высокая

Сейчас: только классификация (`conic`/`conics_classify_*`). В APK — разбор
кривой: канонический вид, центр, фокусы, вершины, сопряжённые вершины,
директриса, радиус, асимптоты. Ключи (30 неиспользуемых): `conics_identify`,
`conics_identify_std_form`, `conics_complete_square(_both)`, `conics_add_*`,
`conics_since_*`, `conics_represents_*`, плюс метки `graph_rt_info_center`,
`graph_rt_info_foci`/`_focus`, `graph_rt_info_vertices`/`_vertex`,
`graph_rt_info_co_vertices`, `graph_rt_info_directrix`, `graph_rt_info_radius`,
`graph_rt_info_canocial_form`, `graph_rt_info_asymptotes`.

Типы узлов: `EQUALS` (квадратичная форма по x,y), `SET`/`LIST`/`INTERVALS`.
Зависимости: E (график). Реализация: выделение полного квадрата для осевых
коник (без члена xy); при повороте — либо приведение поворотом, либо
`SolveError` с явным сообщением.

### R2. Числовые ряды: признаки сравнения/интегральный/Лейбница и формулы сумм — P1, высокая

Сейчас: `ratio_test`, `root_test`, `nth_term_test`, `pseries_test`,
`geom_series_test`, `radius_of_convergence`; `convergence` суммирует через
sympy. Не суммируемые ряды (например, `Σ 1/(n·ln n)`) дают `SolveError` —
APK решает интегральным признаком. Не используется ~193 ключа `series_*`:
`series_integral_test*`, `series_direct_comp_test*`, `series_limit_test*`,
`series_alt_test*`, формулы сумм (`series_find_sum_pos_int/square/cube/even/odd`,
`series_find_sum_geom(_inf)`, `series_formula_*`).

Типы узлов: `SIGMA_DEFINITE`, `LIMIT`, `ABS`. Зависимости: G, K.

### R3. Системы: методы, проверка, нет/бесконечно много, параметры — P1/P2, средняя

Сейчас: Крамер 2×2 + sympy-подстановка для n×n/нелинейных; для параметрических
систем — `SolveError`. Не используется ~160 ключей `system_*`: сложение
(`system_2x2_add`, `system_2x2_add_eqs`), приравнивание (`system_2x2_equalise`),
Крамер по шагам (`system_2x2_cramer_rule`), обратная матрица
(`system_2x2_inv_matrix_*`), проверка (`system_2x2_check_*`), бесконечно много
решений (`system_2x2_any_sol*`, `system_2x2_sol_in_param`, `system_any_sol_param`),
«нет решений» для n×n.

Типы узлов: `SYSTEM`, `MATRIX`, `EQUALS`. Зависимости: M, C.

### R4. Экстремумы на отрезке (концы) — P1, средняя

Сейчас: `extrema` находит критические точки внутри области. Нет учёта концов
отрезка: `extrema_endpoint*`, `extrema_left_i_endpoint`, `extrema_right_d_endpoint`,
`extrema_quad_*`, `extrema_substitute*`, `extrema_final`. Реализация: команда
`extrema_on_interval` (аргументы — границы), сравнение значений в критических
точках и на концах.

### R5. Числовые утилиты — P1/P2, низкая/средняя

- **gcd/lcm/mod**: токены `gcd`/`lcm` ведут в `ABS` (не считаются), `mod` не
  разбирается. Ключи: `animation_lcd_gcd_*` (часть — вариант B), но сами задачи
  самостоятельны.
- **Факторизация**: простые множители, «является ли простым» (потоки
  «Prime Factorization», «Is Prime»).
- **Цифры/разряды**: `Get Digit`, `Get Last/First Digit`, `Get Number of Digits`,
  «американская нотация степеней 10» (`animation_pow10_*`).
- **Округление до разрядов**: до десятков/сотен/тысяч, до десятых/сотых
  (`animation2_rounding_*`), а не только до N знаков после запятой (у нас есть
  `approximate`).

Зависимости: нет.

### R6. Функции как объекты, кусочные и условные — P2, средняя/высокая

Типы узлов не зарегистрированы: `FUNCTION`, `FUNCTION_INVERSE`,
`PIECEWISE_DEFINITION`, `CONDITIONAL_EXPRESSION`. Токены: `fun`, `fun_inv`,
`pw_def`. На графике APK показывает кусочно-линейную форму
(`graph_rt_info_segment_form`). Нужно своё представление определения функции и
вычисление по кускам; продуктовый вопрос — формат ввода.

### R7. Графические аннотации и `/graph` — P1/P2, средняя

29 ключей `graph_rt_*` (корни, вершина, центр, фокусы, асимптоты, область
определения/значений, исключённые/допустимые точки, максимумы/минимумы,
кусочно-линейная форма). Сейчас `/graph` только семплирует. Идея: команда
`graph_info`, возвращающая структурированные аннотации (узлы/множества), и
их отдача в `/graph`.

### R8. Выбор способа решения для многих типов — P2, средняя

`selectMethodText` используется лишь для части уравнений. APK предлагает
переключатель методов для систем, неравенств, интегралов, доказательств,
последовательностей. Обобщить `solve_methods` реестром стратегий.

### R9. Тригонометрические неравенства и метод интервалов — P2, высокая

Тригонометрические неравенства не решаются (sympy даёт лишь главный промежуток
периодического решения). Метод интервалов с «терминаторами» (`rel_terminators_*`,
`rel_root`, `rel_switch`, `rel_solve`) не реализован как отдельный путь. Типы
узлов: интервалы, `UNION`, `ABS`. Зависимости: B, N.

### R10. Глубина шагов по модулям — P2, разная

Не используется ~3034 ключа; крупные модули: `eq_*` 119, `rel_*` 137, `trig_*`
114, `integrate_*` 105, `ineq_*` 98, `extrema_*` 93, `limit_*` 72, `domain_*` 71,
`matrix_*` 65, `seq_*` 63, `frac_*` 49, `compare_*` 45. Делать выборочно по
приоритету модуля: детальные подшаги, альтернативные методы, формулы.

### R11. Столбиковые анимации/рендер (вариант B) — P3, высокая (по решению)

51 поток и ~462 ключа `animation*`/`animation2*`: столбики, чипы, LCD/GCD,
округление, алгебраические плитки, дробь↔десятичная, деление многочленов
(`POLY_DIV_*`). Математика — часть в R5; ценность — в пошаговом рендере и
анимации (уровень приложения).

### R12. Служебные типы узлов и токены — P3, низкая

Не зарегистрированные оформительские типы: `DIFFERENTIAL`, `DERIVATION_DIFF`,
`MATRIX_SPLIT_LAST/CENTER`, `ADD_SUBTRACT(_SIGN)`, `APPROXIMATE(_SIGN)`,
`ALTERNATIVE_FORM`, `EQUALS_SIGN`, `PERIODIC`, `TEXT/TEXT_KEY/EMPTY/STRING/UNKNOWN/
CHOOSE_LOCALIZE/LIST/VERTICAL_LIST`. `LINE_SEGMENT(_LENGTH)` — реализованы
(геометрия APK, см. `09-decisions.md` #75).
Не сопоставленные токены (44): `fun`, `fun_inv`, `pw_def`, `alt_form`, `mod`,
`max`, `min`, `length`, `derivation_prime_var`, `periodic_solution` + внутренние
директивы парсера.

## 11.3a. Прогресс

- **R1** конические сечения — сделано (команда `conic_details`).
- **R2** признаки сходимости — сделано частично: добавлены интегральный
  (`integral_test`) и Лейбниц (`alt_test`), `convergence` переходит к
  интегральному признаку при отсутствии замкнутой суммы. Остаётся: признаки
  сравнения (прямой и предельный) — им нужен ряд-эталон.
- **R3** системы — сделано частично: параметрические решения, «нет решений»,
  проверка (`system_check`). Остаётся: методы сложения/подстановки/обратной
  матрицы как выбираемые способы.
- **R4** экстремумы на отрезке — сделано (`extrema_on_interval`).
- **R5** числовые утилиты — сделано: `gcd`/`lcm`/`mod`,
  `prime_factorization`, `round_place` (до разряда). Остаётся: разряды/цифры и
  американская нотация (по желанию).
- **R7** графические аннотации — сделано: `/api/v1/graph` отдаёт `annotations`
  (корни, экстремумы, асимптоты, пересечение с осью y).

- **R6** кусочные — сделано частично: своё представление `PIECEWISE_DEFINITION`
  (пары «выражение, условие») и команда `piecewise_value`. Остаётся: график
  кусочно-линейной формы (`graph_rt_info_segment_form`).
- **R8** выбор способа — сделано для систем 2×2 (Крамер и подстановка); далее
  распространить на неравенства/интегралы.
- **R9** тригонометрические неравенства — сделано через метод интервалов на
  отрезке (`inequality_on_interval`), ответ корректный (со всеми периодами на
  заданном отрезке).
- **R10** глубина шагов — начато: вид ограничения области определения
  (`domain_poly_real`/`domain_rational`/`domain_even_root`/`domain_log`).
- **R12** служебные типы — сделано: зарегистрированы **все 143** типа узлов
  (геометрия `LINE_SEGMENT*` — см. #75 в `09-decisions.md`).

Дополнено: R2 признаки сравнения (`direct_comparison_test`,
`limit_comparison_test`); R3 способ сложения для 2×2 (`system_2x2_add_eqs`);
R6 график кусочной функции (`/graph`, признак `piecewise`); R10 — подстановка
пределов у определённого интеграла (`integrate_def_bounds`) и формулы
специальных сумм (`series_find_sum_*`).

Углубление R10 (шаги по модулям, все с ключами словаря): пределы
(`limit_solve_const`/`_insert_value`/`limit_poly_msg`), extrema
(`extrema_critical_point`/`_critical_intervals`/`_interval_points`),
интегрирование (`integrate_by_parts_prepare_simple`,
`integrate_differential_sub`, `integrate_def_bounds`), ряды
(`series_find_sum_*`), коники (`conics_complete_square_both`), сравнение
(`compare_frac_*`), комплексные (`complex_find_parts`), системы
(`system_2x2_cramer_rule`), тождества (`prove_identity`), модуль
(`abs_separate`).

Продолжение углубления R10: уравнения (`eq_quad_coeff_identify`,
`eq_quad_disc`, `eq_quad_disc_calculate`), пределы многочленов
(`limit_poly_pos_inf_*`, `limit_poly_neg_inf_*_even/_odd`), перегибы
(`inflection_domain_find`, `inflection_domain_snd_find`), чётность
(`function_even_odd_notation`), последовательности (`seq_check_*`), матрицы
(`matrix_inv_find_formula`), системы 3×3 (`system_3x3_eliminate_var`), ряды
(`series_test_group`), модуль (`abs_separate`), y=kx+b
(`identify_y_intercept_as_const_term`).

Ещё добавлено (`rel_*`/`trig_*`/`matrix_*`/асимптоты): `rel_restrictions_intersect`
перед отсевом корней, `trig_find_period` в тригонометрических уравнениях,
`det2_determinant_rule`/`det3_sarrus_rule`, `def_vert_asymptote`/`def_hor_asymptote`.

Ещё в глубину: дроби (`frac_reduce_reduce`), последовательности

интегралы (`integrate`, `integrate_def_rewrite`), производные (`derive_multi`),
коники-классификация (`conics_identify`, `conics_identify_disc`).

Ещё в глубину (второй проход): комплексные (`complex_calculate_polar`), площадь
(`total_area_fun`, `total_area_x_intercept`), обратная по Гауссу
(`matrix_inv_use_notation`, `matrix_inv_write_right`), сходимость
последовательности (`seq_conv_div_lim`), радиус сходимости
(`convergence_radius_abs`), область определения (`domain_find_defined`),
пересечения с осью x (`one_x_intercept`/`two_x_intercepts`), логарифмы
(`log_def_solve`).

Остаётся: R11 (анимации — по решению пользователя отложены) и остаточная
глубина по редким ключам (`trig_*`, `matrix_*` строками, `integrate_*`/`limit_*`).

Дополнено (по списку пользователя, источник — APK; см. `09-decisions.md` #59–68):

- **R8** выбор способа решения вынесен в **общий механизм** (`solver/methods.py`):
  провайдеры по типу узла, `solve` не знает про конкретные типы.
- **Раскрываемое углублённое пояснение шага** (`subresult`) генерируется для
  шага вычисления значения; показывается блоком «Подробнее».
- Интерфейс: копирование результата, метаданные и обратимая очистка блокнота,
  экран настроек (десятичный знак, нотация бинома, методы умножения/деления),
  предпросмотр ввода и полный каталог **128 операторов** редактора.
- **R6** функции как объекты — **сделано полностью**: узел
  `FUNCTION`/`FUNCTION_INVERSE`, **определения** `f(x) = …` (подстановка `f(2)`,
  производная `f′(x)`, обратная `f⁻¹(a)`), **условное выражение**
  `CONDITIONAL_EXPRESSION` и **кусочная** `PIECEWISE_DEFINITION` (символьный
  узел + значение командой `piecewise_value` + график по ветвям). Определения
  живут в пределах запроса (сервер без состояния).
- **R7** опорные точки графика — **сделано и в приложении**: `GraphData`
  несёт `annotations`, `GraphView` рисует корни, пересечение с осью y,
  экстремумы и асимптоты (пунктиром).
- Углублённые шаги (`subresult`) добавлены для вычисления значения, производной
  и корней квадратного уравнения.

Дополнено (волна «что не умеет решать» — все пункты закрыты, кроме erf):

- **Численное решение смешанных трансцендентных уравнений** (`solver/numeric.py`):
  `sin x = x`, `x·sin x = 1`, `x^x = 2`, `ln x + x = 1`, `|x| + sin x = 1` —
  точные корни берёт `solve`, иначе перебор смен знака на сетке с бисекцией и
  отсевом полюсов; шаги `graph_solution` + `calculate(_plural)`.
- **Параметры в уравнениях**: вторая буква больше не отказ — `x + y = 1`,
  `a·x = 1` решаются автоматически относительно `x` (остальные буквы — параметры),
  способы по буквам через переключатель `selectMethodText` (`eq_param_write`,
  `eq_linear_param_j_final`). Команда `solve_param` осталась явным вариантом.
- **Тригонометрия с параметром и нелинейными сериями** (`trig_equations.py`):
  `sin x = a` и `sin x = cos y` дают серии с `asin(...)` (условие `ConditionSet`
  по параметру снимается), `sin(x²) = 0` — серии формулой от `k`; потолок серий
  поднят до 32.
- **Несколько радикалов**: `√x + √(x+1) = 2` — цикл изоляции и возведений
  (`eq_irrational_simple_square` по шагу на радикал), отбор посторонних корней
  подстановкой.
- **Степень до 16**: потолок `poly_of` поднят (был 8), `x⁹ = 1` решается
  разложением.
- **Периодические неравенства без отрезка**: `sin x > 1/2` даёт
  `(π/6 + 2πk; 5π/6 + 2πk)` — решение на периоде с продолжением сдвигом `kT`;
  `|sin x| > 1/2` — методом интервалов (период π); тождественно верное/пустое —
  `rel_el_of_r`/`rel_el_of_zero`.
- **Производная модуля**: `d/dx |x|` = `sign(x)` (sympy-откат дифференцирует по
  вещественному символу).
- **Поворотные коники** (член `xy`): `conic_details` больше не отказывает —
  поворот осей по собственным векторам формы, канонический вид (`u`,`v`),
  центр, вершины/фокусы/сопряжённые вершины в исходных осях, асимптоты и
  директриса (шаг `conics_identify_std_form`).
- Сообщение отказа для неравенств переписано (прежнее «уравнение с узлом SIN…»
  вводило в заблуждение); `simplify`-откат больше не применяется к отношениям.
- Остаётся честным отказом: первообразные вне элементарных функций (`∫e^(−x²)`
  через `erf` — типа узла в контракте нет).

## 11.4. Порядок работ

1. **R1** конические сечения (замкнутый, ценный).
2. **R2** признаки сходимости и формулы сумм.
3. **R3** системы (методы/проверка/параметры).
4. **R4** экстремумы на отрезке.
5. **R5** числовые утилиты.
6. **R7** графические аннотации (после R1/R4 — из них же данные).
7. **R6** кусочные/условные (после решения по формату).
8. **R9** тригонометрические неравенства.
9. **R8**, **R10** (выборочно по приоритету модулей).
