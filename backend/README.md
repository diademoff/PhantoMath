# backend

Символьный решатель с пошаговым объяснением. Переписывание Photomath 7.10.0
по данным разбора APK.

Контракт ответа воспроизводит оригинальный — см. `truth/03-solver-contract.md`.
Что реализовано на этом этапе: типы AST, структура ответа, резолвер словаря
объяснений. Сам решатель (`POST /solve`) — следующий этап.

## Установка

```bash
uv sync --python 3.12                 # решатель: только sympy
uv sync --python 3.12 --extra api     # + HTTP-слой (FastAPI/pydantic) для API и тестов
```

Модели контракта (`ast.py`, `results.py`) — обычные dataclasses, поэтому
ядро не зависит от `pydantic`/`pydantic-core` (Rust). `pydantic` и `fastapi`
нужны только HTTP-слою (`api.py`) и живут в extra `api`.

## Проверки

```bash
uv run pytest          # тесты (нужен extra api: тесты HTTP-слоя)
uv run ruff check .    # линтер
uv run ruff format .   # форматирование
uv run mypy mymath_backend
```

## Запуск

```bash
uv sync --python 3.12 --extra api
uv run uvicorn mymath_backend.api:app --reload
```

Документация OpenAPI: <http://127.0.0.1:8000/docs>

Путь к словарю объяснений переопределяется переменной
`MYMATH_EXPLANATIONS`; по умолчанию берётся `truth/data/explanations.json`
рядом с репозиторием. Если словаря нет, `GET /api/v1/health` отвечает
`degraded`, а `/solve` работает — просто без текстов пояснений.

## Состав

| Модуль | Что внутри |
|---|---|
| `mymath_backend/node_types.py` | `CoreNodeType` — 143 типа узла, дословно из APK. **Генерируется**, не править руками |
| `mymath_backend/ast.py` | `CoreNode`, `CoreColoredNode`, `CoreAction`, `CoreRichText`; сериализация в формат контракта |
| `mymath_backend/results.py` | `CoreSolverData` и вся ветка вертикального результата: группы, шаги, подшаги |
| `mymath_backend/explanations.py` | Резолвер 3252 шаблонов объяснений на 9 языках |
| `mymath_backend/input.py` | Разбор строки протокола Photomah и AST-JSON в `CoreNode` |
| `mymath_backend/solver/base.py` | Шаги, накопитель результата, реестр модулей по типам узлов |
| `mymath_backend/solver/arithmetic.py` | Первый модуль: `+ - * /`, степени, скобки, точные дроби |
| `mymath_backend/api.py` | FastAPI: `/solve`, `/parse`, `/health` |
| `scripts/gen_node_types.py` | Генератор `node_types.py` из `truth/data/enums.json` |

## Перегенерация типов

`node_types.py` собирается из данных разбора, а не пишется руками:

```bash
uv run python scripts/gen_node_types.py
```

Скрипт падает, если число значений перестало быть 143 или появилось имя,
непригодное как константа Python.

## Словарь объяснений

Данные лежат в `../truth/data/explanations.json` (3252 ключа × 9 языков).
Путь передаётся явно — бэкенд не должен зависеть от расположения файла:

```python
from mymath_backend import load_explanations

explanations = load_explanations("../truth/data/explanations.json")
rendered = explanations.render(
    "abs_const_long",
    args=[CoreNode.variable("x"), CoreNode.constant(7), CoreNode.constant(7)],
    locale="ru",
)
rendered.text  # "Поскольку x, абсолютное значение 7 равно 7"
rendered.links  # кликабельные ссылки «показать другой способ»
rendered.tail_label  # метка в конце строки, отделённая от текста
```

Ключ `CoreRichText.type` разрешается через цепочку `ru-RU -> ru -> default`.
Отсутствующий ключ не поднимает исключение, а даёт `missing_key=True` и
текст `?? step_<ключ> ??` — так дефект виден в логах, а не роняет запрос.

Аргументы рендерит вызывающий: по умолчанию используется текстовый вывод для
логов, фронт подставит свои отрендеренные узлы.

## Тесты

654 теста. Часть работает на полном корпусе объяснений и падает при
расхождении с APK:

- тестовый корпус (`tests/corpus/`, 167 задач по всем 19 модулям)
  воспроизводит эталонные ответы и порядок ключей шагов (см. ниже);

- все 143 имени узла совпадают с `truth/data/enums.json`;
- у всех 3252 ключей есть английский шаблон;
- арность каждого ключа совпадает с максимальным `ARGn` в шаблоне;
- все 3020 ключей из `assets/keys.txt` присутствуют (тест пропускается, если
  APK не распакован);
- каждый ключ, который выдаёт решатель, есть в словаре и его арность
  совпадает с числом `ARG` в шаблоне;
- названия полей ответа совпадают с оригиналом (`solutionNode`, `headers`,
  `description`), а `subresult` отсутствует, когда вложенного результата нет —
  так же ведёт себя Gson, опуская null-поля.

## Тестовый корпус

`tests/corpus/*.json` — по файлу на модуль решателя, 167 задач. Каждая
задача задаёт вход строкой протокола и эталон ручной работы:

```jsonc
{
  "id": "quadratic-two-roots",
  "title": "квадратное: x^2 - 5x + 6 = 0",
  "input": "{=({x^2-5x+6},{0})}",
  "command": "factor",            // необязательно: CoreAction
  "args": ["{…}"],                  // необязательно: аргументы команды
  "interval": {"min": "{0}", "max": "{2pi}"},  // необязательно
  "method": 0,                       // необязательно: индекс способа решения
  "solution": {"type": "LIST", "children": [ … ]},  // null = «нет/бескон.»
  "steps": ["eq_quad_solve_in_r"]    // ключи подшагов по порядку
}
```

Раннер (`tests/test_corpus.py`) сверяет **структуру** ответа
(`CoreNode.structural_eq`, устойчиво к форматированию) и **порядок ключей**
подшагов, а также что каждый ключ есть в словаре объяснений с совпадающей
арностью. Эталоны составлены вручную, а не сняты с решателя: расхождение —
сигнал о дефекте. Так найден и закрыт дефект конвейера
(`../truth/07-open-questions.md`, Q10), кейсы оставлены как регрессия.

## Протокол ввода: константы и обёртки

К строкам протокола добавлены токены, которых не было в `KEYWORD_TO_TYPE`,
но которые есть в нативном словаре (`../truth/data/input-protocol.json`):

| Токен | Узел |
|---|---|
| `pi`, `\pi`, `π` | `CONSTANT "π"` |
| `inf`, `infty`, `\infty`, `∞` | `CONSTANT "∞"` |
| `\i` | `CONSTANT "i"` (мнимая единица; обычная `i` остаётся переменной) |
| `\e` | `CONSTANT "e"` (число Эйлера; обычная `e` остаётся переменной) |
| `deg`, `radian` | `DEGREE`, `RADIAN` |
| `real`, `imag`, `conj` | `REAL`, `IMAGINARY`, `CONJUGATE` |

  интегралы) — см. покрытие в `../truth/06-plan.md`;
